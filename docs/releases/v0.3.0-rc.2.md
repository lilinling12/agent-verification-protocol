# AVP v0.3.0-rc.2 Release Candidate Notes

Status: **SELECTED — NOT PUBLISHED**

- Planned Git tag: `v0.3.0-rc.2`
- Reference distribution version: `0.3.0rc2`
- Release class: prerelease / release candidate
- Exact release source: established only after the release-selection PR is squash-merged to `main` and the resulting `main` commit passes its push-triggered CI/package/conformance gates

`v0.3.0-rc.2` is the governed post-RC1 stabilization candidate. Selecting this version does not create a Git tag, GitHub Release, package-index publication, stable `v0.3.0` release, or Alpha 3 authorization.

## Purpose

RC2 exists to publish and externally validate the materially changed post-RC1 source tree before a separate stable `v0.3.0` decision. It closes the evidence gap identified as SRD-003 only after the actual public RC2 artifacts are downloaded and accepted through the external-consumer release-validation path.

## Protocol and conformance impact

No new normative protocol semantics are selected by this release-management change.

The Alpha 2 normative surface remains governed by AEP-0001 through AEP-0008, the normative specification, requirement indexes, schemas, and language-neutral TCK profiles. Those AEPs are already `Final`; this RC does not alter their lifecycle state.

Post-RC1 stabilization work includes normative-surface closure and reference-runtime alignment verification, but those audits do not reverse protocol authority toward the Python reference implementation.

## Reference implementation changes since RC1

RC2 incorporates the post-RC1 reference-runtime alignment work recorded under `CHANGELOG.md` `Unreleased`, including:

- release identity alignment for FastAPI, OpenTelemetry integration, and the bundled subprocess Oracle runner where those values represent the reference distribution;
- removal of ambiguous public runtime profile self-claims and clearer separation between implementation features and instance configuration;
- correction of Scenario API / Episode manifest identity labels that were previously over-scoped as protocol-wide version claims;
- mandatory Core normal-path TCK execution through the real runtime lifecycle rather than relation-only validation.

These are reference/runtime and evidence-quality corrections unless separately identified by authoritative protocol sources.

## Release provenance and reproducibility

The repository is intentionally placed in governed `release` mode for `0.3.0rc2` before publication.

The exact public release source MUST be the squash-merged `main` commit produced by the release-selection PR. The feature-branch head is not the public release commit and MUST NOT be tagged.

After merge, the final `main` commit must pass the push-triggered package gate, including:

- repository quality checks;
- reproducible wheel and source-distribution builds;
- built-wheel metadata validation;
- clean unconstrained base-wheel installation;
- installed-wheel identity and reference smoke checks;
- separate conformance-environment installation;
- full registered TCK execution from the built wheel;
- exact-commit release-evidence generation and verification.

Only that post-merge `main` SHA may later be proposed for `v0.3.0-rc.2` publication.

## External-consumer acceptance requirement

Pre-publication CI is necessary but does not close SRD-003.

After an explicitly authorized RC2 publication, the governed `Release Validation` workflow must be dispatched with the exact published identity:

- tag `v0.3.0-rc.2`;
- exact published `main` commit;
- version `0.3.0rc2`;
- release class `prerelease`.

The workflow must verify public release metadata and digests, install the downloaded wheel in clean consumer environments, verify installed runtime identity, and run the complete TCK profile set using the exact published release source.

SRD-003 closes only after that public artifact acceptance succeeds.

## Security review

This candidate does not weaken the existing Subject/Evaluator authority boundary, artifact integrity/trust separation, Oracle authority model, protected evaluator material handling, or OpenTelemetry data-minimization boundaries.

Production signed/attested artifact publication remains intentionally optional and is not a prerequisite for this RC unless a separate governance decision changes that scope.

## Known non-goals

This release selection does not authorize or claim:

- stable `v0.3.0` publication;
- PyPI or another package-index publication;
- production-grade signed/attested artifact publication;
- Alpha 3 environment-fabric features;
- stronger process, network, container, VM, tenant, or sandbox isolation than the implementation can demonstrate.

## Publication boundary

This document is release-candidate preparation evidence only.

Creating `v0.3.0-rc.2`, creating a GitHub prerelease, attaching artifacts, or publishing to any package index requires a separate explicit maintainer authorization after the final squash-merged `main` release commit has passed all required exact-commit gates.
