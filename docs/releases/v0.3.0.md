`v0.3.0` is the first intended stable AVP Alpha 2 conformance release. This file records the governed selection of the stable release identity only. It does not create or authorize the public tag, GitHub Release, or package-index publication.

## Protocol and conformance impact

Stable `v0.3.0` promotes the already-closed and already-Final Alpha 2 normative surface to the intended stable conformance baseline. It does not introduce new normative semantics relative to the accepted Alpha 2 surface.

The authority order remains:

1. normative specification;
2. requirement indexes and accepted governing AEPs;
3. schemas and language-neutral TCK;
4. reference implementation.

AEP-0001 through AEP-0008 are `Final`. The reference implementation remains downstream of the protocol and TCK and does not reverse-define normative expectations.

## Compatibility

This stable selection is based on the RC2 evidence line and the post-RC2 reconciliation/audit gates. The stable package version changes from development identity `0.3.0rc3.dev0` to exact stable identity `0.3.0` without intentionally changing protocol semantics.

Downstream consumers should treat `v0.3.0` as the stable Alpha 2 conformance target only after the exact squash-merged release commit is independently green and the stable GitHub Release has been explicitly maintainer-authorized, published, and externally validated.

## Reference implementation

The stable candidate includes the reference-runtime alignment work already exercised through RC2 and subsequent exact-main CI, including:

- distribution-bound FastAPI/OpenTelemetry/Oracle implementation identity where appropriate;
- removal of ambiguous runtime profile self-claims;
- corrected Scenario API and Episode manifest identity scoping;
- mandatory Core normal-path execution through the real runtime lifecycle;
- reproducible package builds and built-wheel conformance execution.

These items remain implementation/evidence alignment unless an authoritative protocol source states otherwise.

## Security review

This stable selection does not weaken existing fail-closed or authority boundaries, including:

- Subject/Evaluator separation;
- protected evaluator material handling;
- Oracle verdict and execution-failure separation;
- immutable Artifact/Evidence integrity checks;
- Artifact Trust claim-honesty requirements;
- OpenTelemetry data-minimization boundaries;
- capability enforcement and hidden-material restrictions.

Production-grade signed/attested artifact publication remains optional and outside this stable publication unless separately governed and authorized. The release does not claim stronger process, network, VM, container, sandbox, or tenant isolation than the implementation demonstrates.

## Release provenance and acceptance requirements

The stable release source is **not yet established by this selection branch**. The feature-branch head must never be used as the release source.

If the selection PR is squash-merged, the resulting exact `main` commit must independently pass push-triggered gates covering:

- repository quality checks on supported Python versions;
- release provenance validation in exact `release` mode;
- reproducible wheel and source-distribution bytes;
- built-wheel metadata validation;
- unconstrained clean-consumer installation;
- installed runtime identity;
- complete registered TCK conformance from the built wheel;
- exact-commit release-evidence build and verification.

Only after those gates succeed may a maintainer separately authorize creation of `v0.3.0` and a non-prerelease GitHub Release. The published stable artifacts must then pass the governed public external-consumer Release Validation path against the exact published identity.

## Known non-goals

This stable selection does not authorize or include:

- PyPI or any other package-index publication;
- signed/attested publication as a mandatory release property;
- Alpha 3 Environment Fabric features;
- new protocol/spec/schema/TCK semantics beyond the already-Final Alpha 2 surface;
- weakening or bypassing release, CI, schema, or TCK validation.
